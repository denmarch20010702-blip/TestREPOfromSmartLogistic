# Boundary Values Analysis — Форма заявки на перевозку

## Контекст

Форма используется для расчёта стоимости перевозки и включает числовые и датовые ограничения:

- Вес груза (кг) — максимум 20 000 кг
- Объём груза (м³) — максимум 82 м³
- Дата погрузки — не может быть в прошлом

---

# 1. Вес груза (kg)

## Допустимый диапазон:
0 – 20 000 кг

## Граничные значения:

| Тип | Значение | Ожидаемый результат |
|-----|----------|---------------------|
| Минимум | 0 | допустимо (если бизнес разрешает пустой груз) |
| Нижняя граница | 1 | допустимо |
| Среднее значение | 10 000 | допустимо |
| Верхняя граница | 20 000 | допустимо |
| Выход за максимум | 20 001 | ошибка валидации |
| Отрицательное | -1 | ошибка валидации |
| Дробное значение | 10.5 | допустимо или округление (уточнить) |
| Пустое значение | null | ошибка обязательного поля |

---

# 2. Объём груза (m³)

## Допустимый диапазон:
0 – 82 м³

## Граничные значения:

| Тип | Значение | Ожидаемый результат |
|-----|----------|---------------------|
| Минимум | 0 | допустимо |
| Нижняя граница | 0.1 | допустимо |
| Среднее значение | 40 | допустимо |
| Верхняя граница | 82 | допустимо |
| Выход за максимум | 82.01 | ошибка валидации |
| Отрицательное | -5 | ошибка валидации |
| Пустое значение | null | ошибка обязательного поля |

---

# 3. Дата погрузки

## Правило:
Дата погрузки не может быть в прошлом относительно текущей даты системы

## Граничные сценарии:

| Тип | Значение | Ожидаемый результат |
|-----|----------|---------------------|
| Прошлая дата | вчера | ошибка валидации |
| Текущая дата | сегодня | допустимо |
| Будущая дата | завтра | допустимо |
| Далёкое будущее | +1 год | допустимо |
| Пустое значение | null | ошибка обязательного поля |

---

# 4. Дополнительные критические проверки

## 4.1 Формат ввода чисел
- 10 (integer) → допустимо
- 10.0 → допустимо
- "10,5" → зависит от локали, потенциальная ошибка
- "ten" → ошибка валидации

---

## 4.2 Системные риски

- overflow при очень больших значениях (например 999999999)
- потеря точности float при расчётах стоимости
- различие клиентской и серверной валидации

---

# 5. Почему эти значения критичны

- Вес и объём напрямую влияют на стоимость расчёта
- Ошибки в граничных значениях могут:
  - приводить к неверной цене
  - ломать API расчёта стоимости
  - вызывать отказ маршрута

Дата критична для логики перевозки и влияет на доступность тарифа и маршрута.

---

# Вывод

Граничные значения являются ключевым уровнем защиты бизнес-логики, так как:
- формируют корректность тарификации
- защищают API от некорректных входных данных
- предотвращают ошибки в логистическом расчёте стоимости
