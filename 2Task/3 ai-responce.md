🔴 Краткий анализ рисков системы (MVP)
Зависимость от внешнего API расчёта стоимости — возможны таймауты, нестабильные ответы, некорректные коды ошибок (особенно “маршрут не найден” vs реальные сбои).
Ошибки валидации географии (города из справочника) — autocomplete может допускать частичное совпадение или «грязный» ввод.
Ошибки в числовых ограничениях веса и объёма — частые edge cases: дробные значения, нули, отрицательные значения, большие числа, форматирование.
Дата погрузки — риск проблем с timezone (сервер vs клиент), а также попытки обхода ограничения “не прошедшие даты”.
UX критичность MVP — любые непонятные ошибки (особенно API) напрямую ломают конверсию заявки.
1. ✅ Позитивные сценарии
Заполнить форму корректными данными:
Город отправления: валидный из справочника
Город назначения: валидный из справочника
Вес: 1500 кг
Объём: 10 м³
Дата: сегодня или будущая дата
→ Нажать “Рассчитать стоимость” → получена цена
Выбор городов через autocomplete:
Ввод 2–3 букв → выбор из списка → значение подставляется корректно
Расчёт стоимости для разных валидных маршрутов:
несколько разных пар городов → успешный ответ API
Использование минимально допустимых корректных значений:
вес = 0.1 кг, объём = 0.01 м³, будущая дата → успешный расчёт
Повторный расчёт с изменением параметров:
изменить вес/объём → получить обновлённую цену без перезагрузки страницы
2. ❌ Негативные сценарии
Город введён вручную не из справочника → попытка расчёта → ошибка валидации
Пустые обязательные поля:
не заполнен город отправления / назначения / вес / объём / дата
Несуществующий маршрут:
валидные города, но API возвращает “маршрут не найден”
Негативные значения:
вес = -10
объём = -5
Некорректный формат чисел:
“10kg”, “ten”, “10,5” (если не поддерживается)
Попытка выбрать прошедшую дату:
datepicker блокирует или ошибка при сабмите
Обрыв сети при расчёте:
запрос отправлен → нет ответа → UI зависает или ошибка
3. 📏 Граничные значения
Вес:
19 999 кг → ок
20 000 кг → ок (максимум)
20 001 кг → ошибка валидации
0 кг → поведение уточнить (скорее ошибка)
Объём:
81.99 м³ → ок
82 м³ → ок
82.01 м³ → ошибка
Дата погрузки:
сегодня → допустимо
завтра → допустимо
вчера → запрещено
Город:
1 совпадающий символ → слишком широкий список
полное совпадение → точный выбор
4. 🎯 UX проверки
Ошибки отображаются рядом с полем, а не в общем алерте
Ошибка “маршрут не найден” объясняется понятным языком (не API-ошибка)
При загрузке API:
кнопка “Рассчитать” disabled или loader показывается
Нет двойного клика:
повторное нажатие не создаёт 2 запроса
Autocomplete:
можно выбрать только элемент из списка
Ошибки не очищают уже введённые данные
При ошибке API пользователь может повторить запрос без перезаполнения формы
5. 🔌 API / интеграционные проверки
Успешный ответ API:
корректная цена отображается на UI
API возвращает “маршрут не найден”:
UI показывает человекочитаемую ошибку
API timeout:
отображается ошибка “Сервис временно недоступен”
API 500 ошибка:
fallback сообщение + возможность повторить запрос
Некорректный JSON ответ:
UI не падает, показывается ошибка
Медленный ответ API (>5–10 сек):
loader + защита от повторных запросов
Дублирующиеся запросы:
backend не должен считать дважды (idempotency проверка)
6. 🧠 Бизнес-логика и ограничения
Нельзя рассчитать стоимость без всех обязательных параметров
Город отправления ≠ город назначения:
если совпадают → ошибка или предупреждение (логистически бессмысленно)
Ограничение веса и объёма:
превышение лимитов блокирует расчёт полностью
Дата погрузки:
должна быть >= текущей даты (учёт часового пояса сервера)
Маршрут должен существовать в тарифной сетке:
иначе “маршрут не найден” (валидный бизнес-ответ)
Комбинации веса/объёма:
возможны скрытые ограничения API (например, слишком большой объём при малом весе)
Защита от спама:
частые клики → throttling / rate limit
