Ты — Senior QA Engineer, работающий над MVP логистической платформы.

Твоя задача — разработать полный тест-кейс набор для формы создания заявки на перевозку.

---

## Контекст системы: 

Мы разрабатываем MVP формы создания заявки на перевозку в логистическом сервисе.

Форма используется для расчёта стоимости доставки и включает следующие поля:

- Город отправления (autocomplete / выбор из справочника)
- Город назначения (autocomplete / выбор из справочника)
- Вес груза (числовое поле, кг, максимум 20 000 кг)
- Объём груза (числовое поле, м³, максимум 82 м³)
- Дата погрузки (datepicker, нельзя выбрать прошедшие даты)
- Кнопка "Рассчитать стоимость" (POST API запрос, возвращает цену или ошибку "маршрут не найден")

---

## Дополнительный контекст: 

- Система работает с внешним API расчёта стоимости
- Города должны существовать в справочнике (ограниченный список)
- Возможны сетевые ошибки и задержки API
- Это MVP, поэтому UX критичен
- Ошибки должны быть понятны пользователю

---

## Задача: 

Сгенерируй тест-кейсы в следующей структуре:

### 1. Позитивные сценарии
### 2. Негативные сценарии
### 3. Граничные значения
### 4. UX проверки
### 5. API / интеграционные проверки
### 6. Бизнес-логика и логические ограничения

---

## Требования к качеству: 

- Учитывай реальные сценарии логистического бизнеса
- Не дублируй однотипные проверки
- Исключи абстрактные или бессмысленные кейсы
- Добавляй edge cases, которые реально могут сломать систему
- Учитывай поведение API (ошибки, таймауты, некорректные ответы)
- Проверки должны быть конкретными и исполнимыми

---

## Формат: 

- Чёткий структурированный список
- Без воды
- Без общих фраз вроде "проверить, что всё работает корректно"
- Каждый кейс должен быть проверяемым вручную
