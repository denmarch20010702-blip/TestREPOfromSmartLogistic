Тестовое задание — Тестирование электронной транспортной накладной (ЭТрН)
1. Описание задания

Данное тестовое задание направлено на проверку навыков анализа требований, понимания бизнес-процессов, работы с XSD-схемами, построения тест-кейсов и негативных сценариев.

Контекст:
Электронная транспортная накладная (ЭТрН), вступающая в силу в рамках регуляторного документооборота.

2. Анализ бизнес-процесса
2.1 Участники процесса
Грузоотправитель
Перевозчик
Водитель
Грузополучатель
Оператор ЭДО
2.2 Титулы ЭТрН
Титул 1 — формирование и подписание ЭТрН грузоотправителем
Титул 2 — принятие груза перевозчиком
Титул 3 — подтверждение получения груза грузополучателем
Титул 4 — завершение перевозки
2.3 Основной бизнес-процесс (Happy Path)
Грузоотправитель создаёт ЭТрН
Заполняет сведения о перевозке
Подписывает титул 1
Отправляет документ через оператора ЭДО
Перевозчик получает документ
Проверяет данные
Принимает груз к перевозке (титул 2)
Начинается перевозка
Грузополучатель получает уведомление
Проверяет груз
Подтверждает получение (титул 3)
Перевозчик завершает перевозку (титул 4)
2.4 Статусы документа
Черновик
Подписан грузоотправителем
Отправлен перевозчику
Получен перевозчиком
Принят к перевозке
В процессе перевозки
Доставлен
Принят грузополучателем
Завершен
3. Анализ XSD-схемы
3.1 Корневой элемент

Документ валидируется через XML-структуру:

<Файл>
3.2 Основная структура документа

ЭТрН содержит следующие основные блоки:

Документ
Сведения о перевозке
Грузоотправитель (СвГО)
Перевозчик (СвПрв)
Грузополучатель (СвГП)
Сведения о грузе (СвГруз)
Сведения о судне (СвСудно)
Сведения о платежах (СвПлатеж)
Подписи (ПодпИнфПрв)
3.3 Ключевой блок “Сведения о грузе (СвГруз)”

Содержит:

описание груза
вес, объём, количество мест
упаковку
контейнеры и пломбы
опасные грузы
дополнительные атрибуты
3.4 Ограничения XSD
Типы данных (string, integer, decimal)
Ограничения длины (minLength / maxLength)
Обязательные поля (use="required")
Количество элементов (minOccurs / maxOccurs)
Форматы дат и чисел
3.5 Бизнес-валидации (Schematron)
Имя файла должно совпадать с ИдФайл
Условная обязательность элементов (зависимость полей)
Контроль наличия пломб при указании номера
Проверка корректности структуры вложенных элементов

5. Негативные сценарии
NEG-001

Создание ЭТрН без обязательных полей

Ожидаемый результат:
Система блокирует сохранение, отображает ошибки валидации.

NEG-002

Отправка неподписанного документа

Ожидаемый результат:
Отправка запрещена системой.

NEG-003

Несоответствие имени файла и ИдФайл

Ожидаемый результат:
Ошибка Schematron-валидации.

NEG-004

Контейнер указан без количества пломб

Ожидаемый результат:
Ошибка бизнес-валидации.

NEG-005

Нарушение последовательности титулов

Ожидаемый результат:
Система блокирует переход статуса.

6. Баг-репорты
BUG-001
Заголовок

Система позволяет отправить ЭТрН без заполнения обязательного реквизита грузополучателя

Шаги воспроизведения
Создать ЭТрН
Не заполнить данные грузополучателя
Подписать документ
Отправить через ЭДО
Фактический результат

Документ успешно отправляется

Ожидаемый результат

Система должна заблокировать отправку и отобразить ошибку валидации

Severity

Critical

BUG-002
Заголовок

Грузополучатель может подтвердить получение груза до завершения перевозки

Шаги воспроизведения
Создать и отправить ЭТрН
Не завершить перевозку
Попытка подтверждения получения груза
Фактический результат

Подтверждение выполняется успешно

Ожидаемый результат

Подтверждение должно быть недоступно до завершения перевозки

Severity

Critical
