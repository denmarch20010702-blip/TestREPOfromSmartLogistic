## Задача 1. Вторая по величине уникальная зарплата

### Условие

Дана таблица:

```sql
Employee (
    id INT PRIMARY KEY,
    salary INT
)
```

Необходимо найти вторую по величине уникальную зарплату.

Если второй по величине зарплаты не существует, запрос должен вернуть NULL.

### Решение

```sql
SELECT (
    SELECT DISTINCT salary
    FROM Employee
    ORDER BY salary DESC
    OFFSET 1
    LIMIT 1
) AS second_highest_salary;
```

### Пояснение

* DISTINCT исключает повторяющиеся значения зарплаты.
* ORDER BY salary DESC сортирует зарплаты по убыванию.
* OFFSET 1 пропускает максимальную зарплату.
* LIMIT 1 возвращает следующую за ней.
* Если второй уникальной зарплаты не существует, подзапрос вернёт NULL.

### Альтернативное решение

С использованием оконной функции DENSE_RANK():

```sql
SELECT salary AS second_highest_salary
FROM (
    SELECT salary,
           DENSE_RANK() OVER (ORDER BY salary DESC) AS salary_rank
    FROM Employee
) t
WHERE salary_rank = 2;
```

Данный вариант также корректно работает с повторяющимися значениями зарплат и демонстрирует использование оконных функций PostgreSQL.

## Задача 2. Поиск дублирующихся email

### Условие

Дана таблица:

```sql
Person (
    id INT PRIMARY KEY,
    email VARCHAR
)
```

Необходимо найти все email-адреса, которые встречаются более одного раза.

### Решение

```sql
SELECT email
FROM Person
GROUP BY email
HAVING COUNT(*) > 1;
```

### Пояснение

* GROUP BY группирует записи по email.
* COUNT(*) подсчитывает количество записей в каждой группе.
* HAVING COUNT(*) > 1 оставляет только дублирующиеся адреса.

### Альтернативное решение

```sql
SELECT DISTINCT p1.email
FROM Person p1
JOIN Person p2
    ON p1.email = p2.email
   AND p1.id <> p2.id;
```

Данный вариант использует самосоединение таблицы, однако является менее оптимальным по сравнению с GROUP BY.

## Задача 3. Клиенты без заказов

### Условие

Даны таблицы:

```sql
Customers (
    id INT PRIMARY KEY,
    name VARCHAR
)
```

```sql
Orders (
    id INT PRIMARY KEY,
    customerId INT
)
```

Необходимо вернуть клиентов, которые ни разу не делали заказов.

### Решение

```sql
SELECT c.*
FROM Customers c
LEFT JOIN Orders o
    ON c.id = o.customerId
WHERE o.customerId IS NULL;
```

### Пояснение

* LEFT JOIN возвращает всех клиентов из таблицы Customers.
* Для клиентов без заказов поля таблицы Orders будут содержать NULL.
* Условие IS NULL оставляет только клиентов без заказов.
* Возвращается полная информация о клиенте.

### Альтернативное решение

```sql
SELECT *
FROM Customers c
WHERE NOT EXISTS (
    SELECT 1
    FROM Orders o
    WHERE o.customerId = c.id
);
```

Решение через NOT EXISTS часто используется в реальных проектах и хорошо масштабируется на больших объёмах данных.

## Проверка граничных случаев

### Задача 1. Вторая зарплата

| Сценарий                                  | Ожидаемый результат         |
| ----------------------------------------- | --------------------------- |
| Только одна уникальная зарплата           | NULL                        |
| Две разные зарплаты                       | Возвращается меньшая из них |
| Несколько одинаковых максимальных зарплат | Дубликаты игнорируются      |
| Пустая таблица                            | NULL                        |

### Задача 2. Дубликаты email

| Сценарий                             | Ожидаемый результат                  |
| ------------------------------------ | ------------------------------------ |
| Все email уникальны                  | Пустой результат                     |
| Один email повторяется несколько раз | Email возвращается один раз          |
| Несколько групп дубликатов           | Возвращаются все дублирующиеся email |

### Задача 3. Клиенты без заказов

| Сценарий                            | Ожидаемый результат                     |
| ----------------------------------- | --------------------------------------- |
| Все клиенты имеют заказы            | Пустой результат                        |
| Ни один клиент не имеет заказов     | Возвращаются все клиенты                |
| Часть клиентов имеет заказы         | Возвращаются только клиенты без заказов |
| Один клиент имеет несколько заказов | Клиент не попадает в выборку            |
