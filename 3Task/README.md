## Задача 1. Вторая по величине уникальная зарплата

### Условие

Дана таблица:

```sql
Employee (
    id INT PRIMARY KEY,
    salary INT
)

Необходимо найти вторую по величине уникальную зарплату.

Если второй по величине зарплаты не существует — вернуть NULL.

Основное решение (оптимальное)
SELECT MAX(salary) AS second_highest_salary
FROM Employee
WHERE salary < (
    SELECT MAX(salary)
    FROM Employee
);
Пояснение
внутренний MAX() определяет максимальную зарплату
внешний MAX() ищет максимум среди значений ниже первого
автоматически исключаются дубликаты без DISTINCT
при отсутствии результата возвращается NULL
Альтернативное решение (оконная функция)
SELECT salary AS second_highest_salary
FROM (
    SELECT salary,
           DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
    FROM Employee
) t
WHERE rnk = 2;
Пояснение
DENSE_RANK учитывает одинаковые значения зарплаты
подходит для задач ранжирования
легко расширяется для top-N логики
Сложность
агрегатное решение: O(n)
оконная функция: O(n log n)
Задача 2. Поиск дублирующихся email
Условие
Person (
    id INT PRIMARY KEY,
    email VARCHAR
)

Необходимо найти email, которые встречаются более одного раза.

Основное решение
SELECT email
FROM Person
GROUP BY email
HAVING COUNT(*) > 1;
Пояснение
GROUP BY формирует группы по email
COUNT(*) определяет частоту появления
HAVING фильтрует только дубликаты
Альтернативное решение
SELECT DISTINCT p1.email
FROM Person p1
JOIN Person p2
    ON p1.email = p2.email
   AND p1.id <> p2.id;
Пояснение
self-join сопоставляет строки между собой
DISTINCT убирает повторяющиеся результаты
демонстрационный, но менее оптимальный подход
Замечание по производительности

Self-join имеет O(n²) сложность и не рекомендуется для больших таблиц по сравнению с GROUP BY.

Задача 3. Клиенты без заказов
Условие
Customers (
    id INT PRIMARY KEY,
    name VARCHAR
)

Orders (
    id INT PRIMARY KEY,
    customerId INT
)
Основное решение
SELECT c.*
FROM Customers c
LEFT JOIN Orders o
    ON c.id = o.customerId
WHERE o.customerId IS NULL;
Пояснение
LEFT JOIN сохраняет всех клиентов
отсутствие связанного заказа определяется через NULL
классический anti-join паттерн
Альтернативное решение
SELECT c.*
FROM Customers c
WHERE NOT EXISTS (
    SELECT 1
    FROM Orders o
    WHERE o.customerId = c.id
);
Пояснение
NOT EXISTS устойчив к NULL-значениям
часто лучше оптимизируется в PostgreSQL
предпочтителен для больших объёмов данных
